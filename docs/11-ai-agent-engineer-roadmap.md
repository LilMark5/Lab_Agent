# 11 · AI Agent 工程师成长路线

## 1. AI Agent 工程师到底在做什么？

不是只写 Prompt，而是把大模型变成可靠的生产系统：

```text
理解业务 -> 设计工具 -> 组装工作流 -> 控制成本与安全 -> 上线并监控
```

Agent 工程师 = 软件工程能力 + 大模型能力 + 产品判断。

## 2. 以本项目为例，你掌握了哪些能力？
\
- **软件工程**：FastAPI 分层、SQLAlchemy、Vue3、JWT。
- **模型调用**：OpenAI 兼容协议、消息管理、流式输出。
- **检索**：向量化、ChromaDB、RAG。
- **工具**：函数 Schema、Tool Calling、真实业务落库。
- **编排**：LangGraph 状态图、条件边、工具节点。
- **工程安全**：权限、确认机制、异常兜底。

## 3. 学习阶段建议

### 阶段一：把基础打牢

先不要追最新框架：

- Python：类型、装饰器、生成器、异步。
- Web：HTTP、REST、JSON、跨域。
- 数据库：SQL、事务、索引。
- 前端：至少读懂 Vue/React，能调试。

### 阶段二：吃透一次模型调用

直接用 OpenAI SDK 写一个完整聊天接口，理解：

- system / user / assistant 消息。
- temperature、max_tokens。
- 流式响应。
- token 与成本。

### 阶段三：做 RAG 项目

从一个真实文档库开始，自己实现：

- 文档加载与切块。
- embedding 与向量检索。
- top-k、相似度过滤。
- 评估检索是否命中。

### 阶段四：做 Tool Calling 项目

让模型查真实数据、写真实数据。重点体验“模型说、后端做”的边界。

### 阶段五：学 LangGraph 编排

理解 State、Node、Edge，做一个有确认环节的多步 Agent。

### 阶段六：生产化

加日志、监控、限流、缓存、成本统计、A/B 测试、Prompt 版本管理。

## 4. 建议掌握的进阶主题

### 4.1 结构化输出

让模型返回 JSON，而不是自由文本。用于抽取实体、生成表单。

### 4.2 记忆

短期记忆是消息列表；长期记忆要存数据库，注意隐私和遗忘机制。

### 4.3 评估

Agent 质量不能靠“感觉”。要有评测集、准确率、延迟、成本、成功率。

### 4.4 多 Agent

当单个 Agent 职责过重，可以拆分：规划者、执行者、评审者。
LangGraph 支持 supervisor、并行、循环等多种拓扑。

### 4.5 可观测性

记录每次工具调用、token 数、延迟，推荐了解 LangSmith 或自建日志链路。

### 4.6 安全

Prompt 注入、越权工具调用、敏感数据外泄。写工具前先问：
“这个函数如果被恶意调用，会发生什么？”

## 5. 面试中可能被问到的问题

- RAG 和微调的区别？什么场景用哪个？
- Tool Calling 中，模型会执行工具吗？
- 为什么 Agent 要限制工具循环次数？
- 向量检索为什么比关键词检索更鲁棒？
- 如何降低大模型幻觉？
- 如何给 AI 应用做安全和权限设计？

## 6. 你可以继续做的项目

- 给预约系统加“邮件/短信提醒”。
- 给 RAG 加文档管理后台，支持增量更新。
- 给 Agent 加 Human-in-the-loop 审核。
- 用 LangGraph 做多 Agent 的课程顾问。
- 给系统加 LangSmith 或自建观测链路。

## 7. 最后：学习 Agent 的正确姿势

1. 小步验证：先让一个工具跑通，再加第二个。
2. 读官方文档：LangChain/LangGraph 更新快，二手教程容易过时。
3. 关注成本：每次调01模型前，估算这步值不值。
4. 保留“不用框架也能讲清”的能力：先懂原理，再用框架。
