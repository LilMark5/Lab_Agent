# 22. 项目总结（截至 2026-10-16）

对项目当前状态的一次全面盘点：架构、功能、质量保障（测试 + 评估）、
已知问题与后续路线。数据均来自本轮实测，不是凭记忆写的。

## 1. 项目是什么

智能实验室预约系统：从传统 CRUD（实验室 / 设备 / 预约 / 用户）
逐步升级到带 RAG 知识库与工具调用能力的 AI Agent 全栈应用，
定位为毕业设计 / AI Agent 实习简历项目。

## 4. 测试覆盖了什么

21 个用例集中在五条链路，都是确定性测试（不依赖外部 LLM）：

- **Agent 服务**（7）：路由有无工具调用、interrupt 审批闭环、
  多轮历史不重复、schema 兼容 thread_id、图编译。
- **知识库切块**（4）：短文本单块、块大小约束、重叠保留、元数据。
- **文档解析**（3）：文本解析、不支持扩展名拒绝、document_id 传递。
- **检索服务**（5）：RRF 按 chunk_id 融合、块来自向量库、
  BM25 覆盖上传文档、检索范围参数、include_uploaded 开关。
- **预约服务**（2）：时间重叠拒绝 + 空档接受、并发预约不重复落库
  （SELECT FOR UPDATE）。

**没覆盖到的**：API 层（FastAPI 路由/鉴权）、SSE 流式、
前端无任何测试。这是测试金字塔上明显的缺口。

## 5. 已知问题（按影响排序）

1. **评估语料太小**：内置知识库仅 4 篇而检索 top_k=5，三种检索策略
   Hit@K 全满分已饱和，检索策略对比在扩语料前没有说服力。
2. **判官模型噪声**：被测模型与裁判模型同为 deepseek-v4-flash，
   等于考生自己阅卷；下一步应换更强的独立裁判模型。
3. **前端主 chunk 1.2MB**（gzip 386KB）：Element Plus 全量引入导致，
   应做按需引入或 manualChunks 拆包。
4. **知识库管理接口权限**：`kb.py` 只要求登录，未限定管理员。
5. **遗留技术债**：同步 SQLAlchemy、无 CI、Docker 未实跑验证、
   Agent 侧（工具选择准确率、审批触发率）无评估指标。

## 6. 后续路线建议

1. 扩充评测语料到 30~50 篇，让检索指标重新有区分度。
2. 裁判模型与被测模型分离，评估接入「改 prompt / 换模型后自动跑」的流程。
3. 补 API 层集成测试（FastAPI TestClient）与前端关键路径测试。
4. 知识库接口限管理员；前端拆包优化首屏。
5. 多智能体扩展（状态里已预留 approval 字段）。
