# 第 01 章 · 先跑起来：十分钟上手

## 开篇：为什么必须亲手跑一遍

我在写这本书时做过一个实验：把同一份 `agent_service.py` 给两个人看。

- A 君读了 20 分钟，说「看懂了，就是 LangGraph 建个图」。
- B 君花 15 分钟把项目跑起来，发了一条「帮我预约明天的实验室」，看着终端日志里 Agent 思考了 3 次、调用了 2 个工具、然后在写库前停住弹出确认卡片——然后他回来问了一堆问题：
  - 「为什么它停下来了？」
  - 「如果我不确认，这个状态存在哪？」
  - 「重启服务后它还记得我刚才说了什么吗？」

**B 君的学习效率是 A 君的 5 倍以上**，因为他看到了**动态行为**，而 A 君只看到了静态结构。

Agent 程序的本质是**运行时行为不确定**——这正是它难学的地方，也是必须跑起来看的原因。

这一章的目标很朴素：**让这个项目在你机器上跑起来，发出第一条对话，看到 Agent 思考的全过程。**

## 一、先搞清楚要跑几个进程

一个常见的新手困惑：「这个项目到底怎么启动？是不是一条命令？」

答案是：**至少两个进程**（开发模式下）。

```
┌─────────────────────┐          ┌─────────────────────┐
│   前端 Vite Dev     │  HTTP    │   后端 FastAPI      │
│   localhost:5173    │ ───────► │   localhost:8000    │
│   (Vue3 + Element)  │  SSE     │   (Uvicorn)         │
└─────────────────────┘          └──────────┬──────────┘
                                            │
                                            ├──► 数据库（SQLite 文件 / PostgreSQL）
                                            ├──► 向量库（Chroma 本地目录 / pgvector）
                                            ├──► 大模型 API（DeepSeek / OpenAI 兼容）
                                            └──► checkpointer（SQLite / PG）
```

**为什么不是一个进程？**

因为前后端分离。开发时 Vite 提供热更新，生产时前端打包成静态文件由 Nginx 托管，后端只提供 API。这是标准做法，不是这个项目瞎搞。

> ⚠️ **坑预警**：不要试图用 `python -m http.server` 直接打开前端的 `index.html`。前端需要 Vite 处理 `.vue` 单文件组件和路径别名（`@/`）。

### 可选第三个进程：MCP 服务

项目里有一个独立的 `mcp_server.py`，用 FastMCP 暴露只读工具。它**可以不启动**——Agent 默认用进程内工具，只有配置 `MCP_ENABLED=true` 时才去连它。

第 30 章会详细讲，这一章先不管。

## 二、环境准备

### 2.1 Python 版本（这里有个真实的坑）

项目推荐 **Python 3.11 或 3.12**，不是越高越好。

**真实事故**：这台机器上装了 Python 3.14，结果 `pip install` 时多个包（尤其是 `psycopg2-binary`、`sentence-transformers` 依赖的科学计算包）没有 3.14 的预编译 wheel，需要源码编译，编译又缺 Visual C++ 工具链，卡了很久。

**解法**：项目里专门建了一个干净的虚拟环境 `.venv-clean`（Python 3.11）。

```powershell
# 检查你的 Python 版本
python --version
# 如果是 3.14，强烈建议装一个 3.11 或用 py 启动器
py -3.11 --version
```

> **面试话术**：「为什么选 3.11？因为 AI 生态的预编译包最全，3.14 上很多包要源码编译，Windows 下容易失败。这是个很实际的工程约束。」——这句话能体现你在真实环境里踩过坑。

**几个关键配置的真实含义**：

| 配置项 | 默认值 | 不配会怎样 | 章节 |

> ⚠️ **诚实口径**：项目里 `REDIS_URL` 是空的，`CHECKPOINT_DATABASE_URL` 也没配。面试时说「Redis 已接入但未启用，做了优雅降级」比说「用了 Redis 做缓存」安全得多。

### 3.2 启动时到底发生了什么（重点）

很多人跑起来就不管了，但**启动过程本身就是一道面试题**。项目入口 `app/main.py` 用了 FastAPI 的 `lifespan` 机制：

```python
# backend/app/main.py（简化）
@asynccontextmanager
async def lifespan(app: FastAPI):
    # ── 启动时执行 ──
    init_db()                    # 建表（没有 Alembic 时兜底）
    await warmup_embedding()     # 预热 embedding 模型
    yield
    # ── 关闭时执行 ──
    await close_vector_store()   # 释放向量库连接

app = FastAPI(title="...", lifespan=lifespan)
```

**为什么要 `lifespan` 而不是在模块顶层直接写？**

三个理由，都能拿去面试讲：

1. **可测试**。模块顶层代码在 `import` 时就执行，导致你没法在测试里控制初始化顺序。用 `lifespan` 的话，测试可以用 `TestClient` 的上下文管理器精确控制。
2. **异步**。模块顶层不能 `await`，但预热 embedding 模型（加载几百 MB 的模型权重）是 IO 密集的，异步更好。
3. **配对清理**。资源申请和释放写在同一个函数里，不会漏。如果写在顶层，关闭逻辑没地方放。

**为什么预热 embedding 模型？**

因为 `sentence-transformers` 首次调用要下载/加载模型（bge-small-zh-v1.5 约 130MB），冷启动第一次检索可能要等 10 秒。预热后，用户第一次提问就是快的。

> 💡 **面试话术**：「我把模型预热放在 lifespan 里，是为了避免第一个用户承担冷启动延迟。这是 Agent 应用很常见的优化——模型加载、向量库连接、甚至向量索引的warm-up 都应该在服务启动时做完。」

### 前端和后端怎么连上的

看 `frontend/vite.config.js` 里的 proxy 配置：

```js
server: {
  proxy: {
    '/api': {
      target: 'http://localhost:8000',
      changeOrigin: true,
    }
  }
}
```

**为什么要代理？**

因为不代理的话，前端 `localhost:5173` 请求后端 `localhost:8000` 会触发浏览器的**同源策略**限制（CORS）。

开发时用 Vite 代理，请求看起来是同源的（都是 5173），由 Vite 转发给 8000，**浏览器认为没有跨域**。

生产环境则是 Nginx 反向代理，或者直接配 CORS 白名单。

> 💡 **面试话术**：「开发环境我用 Vite proxy 避免 CORS，生产环境用 Nginx 反代。CORS 我也配了，但白名单限定具体域名而不是 `*`，因为 `*` 和带 credentials 的请求不能共存。」

## 五、发出第一条对话（关键实验）

### 5.1 注册 / 登录

1. 打开 http://localhost:5173
2. 注册一个账号（角色选 student）
3. 登录后进入 **AI 对话** 页面

### 5.2 先问一个知识库问题

如果知识库是空的，先以管理员身份上传一份文档（PDF/Word/Markdown 都行），比如《实验室安全管理规定》。

然后问：

```
实验室里能不能带食物进去？
```

**你应该看到的**：回答下面有引用来源，能点开看原文出处。

**背后发生了什么**（第 21-29 章详解）：

```
你的问题
  ↓ 查询改写（口语 → 检索式）
  ↓ 向量召回 top20 + BM25 召回 top20
  ↓ RRF 融合 → top10
  ↓ CrossEncoder 重排 → top3
  ↓ 扩展父上下文（把碎片补成完整段落）
  ↓ 拼进 prompt → 模型回答
  ↓ 附带引用溯源
```

### 5.3 再问一个需要工具的问题（重点）

```
帮我查一下有哪些实验室
```

**你应该看到的**：Agent 调用了 `search_labs` 工具，返回列表。

### 5.4 触发人工审批（最关键）

```
帮我预约 A301 实验室，明天下午 2 点到 5 点
```

**你应该看到的**：

```
┌────────────────────────────────────┐
│  ⚠️ 需要确认                        │
│  工具：create_reservation          │
│  参数：{"lab_id": 1, ...}          │
│  [ 确认 ]  [ 取消 ]                │
└────────────────────────────────────┘
```

点**取消**，Agent 会说「用户取消了本次操作，未执行」。
点**确认**，Agent 才真的写库。

**这就是 Human-in-the-Loop（第 18 章）**。它是这个项目最值得讲的点之一，因为大部分教程里的 Agent 都是直接写库的，没有这道保险。

### 5.5 观察终端日志

后端终端会打印类似：

```
[agent] 调用模型，消息数=3
[agent] 模型返回 tool_calls: [search_labs]
[approval] 命中只读工具，跳过审批
[tools] 执行 search_labs
[agent] 第 2 次调用模型
[agent] 模型返回 tool_calls: [create_reservation]
[approval] 命中写库工具，interrupt 暂停
[用户确认]
[tools] 执行 create_reservation
[agent] 第 3 次调用模型 → 生成最终回答
```

**这个「思考多次」的循环，就是 ReAct + LangGraph 的运行时表现**。第 14、15 章会拆解它。

```bash
curl -X POST http://localhost:8000/api/ai/chat \
  -H "Content-Type: application/json" \
```

### 6.3 调用 Agent（流式 SSE）

```bash
curl -N -X POST http://localhost:8000/api/ai/chat/stream \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer eyJhbGciOiJIUzI1NiIs..." \
  -d '{"thread_id":"my-thread-001","messages":[{"role":"user","content":"有哪些实验室"}]}'
```

你会看到一个个 `data: {...}` 事件流出来。**`-N` 参数是禁用 curl 缓冲，不加的话看不到流式效果**。

> ⚠️ **坑预警**：`curl` 不加 `-N`，SSE 会被缓冲，你会以为流式没生效。这个坑我踩过。同理，Nginx 反代时要关掉 `proxy_buffering`，前端要设 `X-Accel-Buffering: no`（第 31 章）。

## 八、最小可运行骨架：50 行跑通一个带工具的 Agent

如果项目跑不起来，或者你想先理解本质，用下面这个**自包含**的文件验证。它不需要数据库、不需要前端，只需要一个 API Key。

```python
"""
minimal_agent.py —— 最小可运行的 Agent
演示：模型自主决定调用工具 → 执行 → 拿结果 → 再回答
运行：python minimal_agent.py
"""
import asyncio
import json
from typing import Annotated

from langchain_core.messages import AIMessage, HumanMessage, SystemMessage, ToolMessage
from langchain_core.tools import tool
from langchain_openai import ChatOpenAI
from langgraph.graph import END, START, StateGraph
from langgraph.graph.message import add_messages
from typing_extensions import TypedDict

# ── 1. 定义工具 ──────────────────────────────────────────────
# @tool 装饰器会把函数的 docstring 和类型注解转成 JSON Schema 发给模型。
# 所以 docstring 不是注释，是模型判断"什么时候用这个工具"的唯一依据。
@tool
def search_labs(keyword: str) -> str:
    """根据关键词搜索实验室。当用户想找某个实验室、询问有哪些实验室时调用。"""
    fake_db = [
        {"id": 1, "name": "A301 细胞生物学实验室", "capacity": 20},
        {"id": 2, "name": "B205 材料分析实验室", "capacity": 15},
    ]
    matched = [x for x in fake_db if keyword in x["name"] or not keyword]
    return json.dumps(matched, ensure_ascii=False)


TOOLS = [search_labs]
TOOLS_BY_NAME = {t.name: t for t in TOOLS}

# ── 2. 定义状态 ──────────────────────────────────────────────
# add_messages 是 LangGraph 提供的 reducer：
# 节点返回 {"messages": [msg]} 时，它执行的是"追加"而不是"覆盖"。
class AgentState(TypedDict):
    messages: Annotated[list, add_messages]

# ── 3. 建图 ──────────────────────────────────────────────────
async def build():
    # bind_tools 把工具的 schema 注入模型请求，模型才知道有哪些工具可用
    llm = ChatOpenAI(
        api_key="sk-你的key",
        base_url="https://api.deepseek.com/v1",
        model="deepseek-chat",
        temperature=0,
    ).bind_tools(TOOLS)

    async def agent_node(state: AgentState) -> dict:
        """agent 节点：让模型决定下一步。"""
        response = await llm.ainvoke([
            SystemMessage(content="你是一个实验室预约助手，可以调用工具查询信息。"),
            *state["messages"],
        ])
        return {"messages": [response]}

    async def tool_node(state: AgentState) -> dict:
        """tool 节点：执行模型请求的工具。"""
        last = state["messages"][-1]
        results = []
        for tc in getattr(last, "tool_calls", []) or []:
            fn = TOOLS_BY_NAME.get(tc["name"])
            # 关键：工具不存在时不能抛异常中断图，要回填错误信息让模型自纠
            content = fn.invoke(tc["args"]) if fn else f"未找到工具：{tc['name']}"
            results.append(ToolMessage(content=content, tool_call_id=tc["id"]))
        return {"messages": results}

    def route(state: AgentState) -> str:
        """路由：模型返回的最后一条消息有没有 tool_calls，决定是继续调工具还是结束。"""
        last = state["messages"][-1]
        return "tools" if getattr(last, "tool_calls", None) else END

    g = StateGraph(AgentState)
    g.add_node("agent", agent_node)
    g.add_node("tools", tool_node)
    g.add_edge(START, "agent")
    g.add_conditional_edges("agent", route, {"tools": "tools", END: END})
    g.add_edge("tools", "agent")   # 工具执行完回到 agent，形成循环
    return g.compile()

# ── 4. 运行 ──────────────────────────────────────────────────
async def main():
    graph = await build()
    async for event in graph.astream(
        {"messages": [HumanMessage(content="有哪些细胞相关的实验室？")]},
        {"recursion_limit": 10},   # 必须设！否则模型死循环会无限调用
    ):
        for node, value in event.items():
            msgs = value.get("messages", [])
            for m in msgs:
                kind = type(m).__name__
                if kind == "AIMessage":
                    calls = getattr(m, "tool_calls", None)
                    print(f"[agent] {m.content or ''} tool_calls={calls}")
                else:
                    print(f"[{node}] {m.content[:200]}")

if __name__ == "__main__":
    asyncio.run(main())
```

**预期输出**（你会看到 agent → tools → agent 的循环）：

```
[agent]  tool_calls=[{'name': 'search_labs', 'args': {'keyword': '细胞'}, 'id': 'call_001'}]
[tools] [{"id": 1, "name": "A301 细胞生物学实验室", "capacity": 20}]
[agent] 找到了 1 个相关实验室：A301 细胞生物学实验室，可容纳 20 人。 tool_calls=None
```

**这段代码里藏着的 8 个关键点**（都是面试考点）：

| # | 点 | 为什么重要 |
|---|---|---|
| 1 | `@tool` 的 docstring | 模型靠它判断何时调用，写得含糊会导致乱调用 |
| 2 | `add_messages` reducer | 没有它，每次返回会覆盖历史，多轮对话失效 |
| 3 | `bind_tools` | 不加这行模型永远不知道有工具 |
| 4 | `tool_calls` 结构 | `{"name", "args", "id"}`，`id` 用于配对结果 |
| 5 | `ToolMessage.tool_call_id` | 必须和 `tool_calls.id` 一致，否则 API 报 400 |
| 6 | 工具不存在时回填错误 | 抛异常会中断整个图，回填才能让模型自纠 |
| 7 | `recursion_limit` | **不设会无限循环烧钱**，这是最贵的坑 |
| 8 | `tools → agent` 这条边 | 它构成了 ReAct 循环的"回到思考" |

**为什么用 `pydantic-settings` 而不是 `os.getenv`？**

1. **类型自动转换**：`os.getenv` 返回的一律是字符串，你要自己 `int()`。`BaseSettings` 按注解自动转。
2. **集中声明**：所有配置在一个类里，一眼看全，不用满项目找 `os.getenv`。
3. **IDE 补全**：`settings.` 后面能自动补全，拼错了立刻发现。
4. **校验**：可以加 `Field(gt=0)` 这类约束，启动时就发现非法配置。

## 十、常见启动故障排查表

| 现象 | 根因 | 解法 |
|---|---|---|
| `ModuleNotFoundError: No module named 'app'` | 不在 backend 目录 | `cd backend` 再启动 |
| 端口被占用 | 8000 已被占 | `--port 8001` 或杀掉占用进程 |
| `未配置大模型 API Key` | `.env` 没配或没生效 | 确认 `.env` 在 backend 目录，且重启了服务 |
| 前端 404 | 路径别名问题 | 检查 `vite.config.js` 的 `@` 别名 |
| 前端接口 502 | 后端没起或 proxy 配错 | 检查 Vite proxy target |
| `pip install` 编译失败 | Python 版本过高 | 换 3.11 |
| Chroma 报 telemetries 错 | Chroma 版本问题 | 设 `ANONYMIZED_TELEMETRY=False` |
| embedding 模型下载慢 | HuggingFace 被墙 | 设 `HF_ENDPOINT=https://hf-mirror.com` |
| 流式不生效 | curl 没加 `-N` / Nginx 缓冲 | 见第 31 章 |

> ⚠️ **真实坑**：`sentence-transformers` 首次会从 HuggingFace 下载 bge-small-zh-v1.5，国内经常超时。解法是设镜像环境变量：
> ```powershell
> $env:HF_ENDPOINT = "https://hf-mirror.com"
> ```
> 这个坑我踩过两次，第二次才记住。

## 面试问答：环境与上手

### Q1：「你这个项目怎么启动？依赖有哪些？」

**满分答法**：

> 前后端分离，开发时两个进程。后端 `uvicorn app.main:app --reload`，前端 `npm run dev`。前端通过 Vite proxy 把 `/api` 转发到后端 8000，避免开发环境跨域。
>
> 依赖分几层：Web 是 FastAPI + Uvicorn；数据层 SQLAlchemy 2.0 + Alembic；AI 层是 LangChain Core + LangGraph + langchain-openai；向量层是 Chroma 加 sentence-transformers 做 embedding；检索层有 rank-bm25 做关键词召回；文档解析用 pypdf 和 python-docx；工具协议用 mcp 和 langchain-mcp-adapters。
>
> 有个实际约束：Python 版本我用 3.11，因为 3.14 上 psycopg2 这类包没有预编译 wheel，Windows 下要源码编译容易失败。

---

### Q2：「启动时做了什么初始化？为什么？」

**满分答法**：

> 用 FastAPI 的 lifespan 做了三件事：建表、预热 embedding 模型、注册关闭时的资源释放。
>
> 关键是预热 embedding。sentence-transformers 首次加载 bge-small-zh-v1.5 要加载一百多 MB 的权重，冷启动第一次检索可能要等十秒。预热之后用户第一次提问就是快的。
>
> 用 lifespan 而不是模块顶层代码，是因为顶层代码在 import 时就执行，测试里没法控制初始化顺序；而且顶层不能 await，但模型加载是 IO 密集的。lifespan 还能保证申请和释放配对写在同一个函数里，不会漏。

---

### Q3：「怎么验证你的 Agent 真的能工作？」

**满分答法**：

> 三层验证：
>
> 一是自动化测试，37 个 pytest 用例。Agent 部分我注入假 LLM，让它按预设脚本返回 tool_calls，这样执行路径确定，可以精确断言「审批节点有没有触发」「工具重试了几次」「历史被裁剪成几条」。
>
> 二是手动验证五个场景：多轮记忆指代、写库人工审批、并发防超卖、长对话不崩、工具超时兜底。
>
> 三是离线评测，14 条标注用例跑 RAGAS，看 faithfulness、answer_relevancy 这些指标。
>
> 另外我会看终端日志，追踪 Agent 每一轮调用了什么工具、返回了什么，这是排查「模型为什么不调工具」最快的方式。

---

### Q4：「如果我不配 API Key，你的系统会怎么处理？」

**满分答法**：

> `build_agent` 第一行就检查 `settings.LLM_API_KEY`，没配直接抛 `BusinessException`，返回统一的错误响应，而不是让请求打到模型那边才失败。
>
> 这是「快速失败」原则——配置问题应该在启动或第一次调用时立刻暴露，不要拖到运行时深处才抛一个看不懂的错误。统一异常处理器会把它包装成 `{code, message, data}` 结构返回给前端，前端弹一个明确的提示。

---

### Q5：「开发环境和生产环境的差异你怎么处理？」

**满分答法**：

> 配置全部走 `pydantic-settings`，从 `.env` 读，不同环境换 `.env` 就行，代码不用改。
>
> 具体差异：数据库开发用 SQLite 零配置，生产用 PostgreSQL；checkpointer 同理，开发 SQLite，生产 PG；向量库开发用 Chroma 本地目录，生产用 pgvector 复用主库省一个组件；CORS 开发用 Vite proxy 绕过，生产用 Nginx 反代加白名单。
>
> 需要强调的是，SQLite 在生产上有个真问题：它的写锁是整库锁，并发写会互相阻塞，而且 `SELECT FOR UPDATE` 在 SQLite 上实际退化成整库锁，导致并发测试「假通过」。所以生产必须换 PG。（第 11 章会细讲）

## 常见坑

### 坑 1：Python 版本过高导致依赖装不上

3.14 上很多 AI 生态包没有预编译 wheel。**老老实实用 3.11**。

### 坑 2：改了 `.env` 不生效

`pydantic-settings` 在 import 时读一次，改了要**重启服务**。`--reload` 对 `.env` 的改动不敏感。

### 坑 3：SSE 看不到流式

三重原因：curl 没加 `-N`、Nginx 开了 `proxy_buffering`、响应头没设 `X-Accel-Buffering: no`。第 31 章逐个击破。

### 坑 4：忘了 `recursion_limit`

模型死循环调用工具，一晚上烧掉几百块。**必设**。

### 坑 5：HuggingFace 模型下载超时

设 `HF_ENDPOINT=https://hf-mirror.com`。

### 坑 6：把「项目跑起来了」当成「学会了」

跑起来只是起点。做完本章的五个实验才算数。
