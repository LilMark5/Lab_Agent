# 第 09 章 · 依赖注入

## 开篇：一个「组件怎么拿到它需要的东西」的问题

假设你的路由需要：数据库会话、当前用户、配置、限流器。

**方案 A：全局变量**

```python
# config.py
settings = Settings()

# main.py
engine = create_engine(...)
SessionLocal = sessionmaker(...)

# api/reservation.py
from app.main import SessionLocal   # ← 循环导入！main 导入了 api
from app.config import settings

def create_reservation(data):
    db = SessionLocal()
    ...
```

**问题**：

1. **循环导入**：`main.py` 导入 `api`，`api` 又导入 `main`
2. **无法测试**：测试时想换成内存数据库，得 monkey-patch 全局变量
3. **生命周期不受控**：谁来关闭这个 Session？
4. **隐式依赖**：看函数签名不知道它依赖什么

**方案 B：参数传入**

```python
def create_reservation(data, db, current_user, settings, limiter):
    ...

# 调用方要自己准备所有东西
@app.post("/reservation")
def route(data: ReservationCreate):
    db = SessionLocal()
    user = decode_jwt(request.headers["Authorization"])
    limiter = RedisLimiter(...)
    return create_reservation(data, db, user, settings, limiter)
```

**问题**：每个路由都要重复组装一遍。

**方案 C：依赖注入**

```python
@app.post("/reservation")
def route(
    data: ReservationCreate,
    db: Session = Depends(get_db),                 # ← 声明依赖
    user: User = Depends(get_current_user),        # ← 声明依赖
    limiter: Limiter = Depends(get_limiter),       # ← 声明依赖
):
    return create_reservation(data, db, user)
```

**FastAPI 自动解析这些依赖，调用你的函数。**

好处：

| 好处 | 说明 |
|---|---|
| 显式依赖 | 看签名就知道需要什么 |
| 可复用 | 声明一次，处处可用 |
| 可测试 | 测试时替换依赖即可（关键！） |
| 生命周期 | `yield` 保证清理 |
| 文档 | Swagger 自动显示 |

## 一、Depends 的工作原理

### 1.1 解析过程

当你写：

```python
def route(
    db: Session = Depends(get_db),
    user: User = Depends(get_current_user),
): ...
```

FastAPI 在**启动时**（不是运行时）做这些事：

```
1. 扫描路由函数的参数
2. 发现 db 的默认值是 Depends(get_db)
3. 分析 get_db 的签名 → 它自己有没有依赖？
   - 没有 → 它是最底层的
4. 发现 user 的默认值是 Depends(get_current_user)
5. 分析 get_current_user 的签名 → 它有依赖！
   - credentials: Security(security)
   - db: Depends(get_db)   ← 又是一个依赖！
6. 递归解析 get_db → 已经解析过了，复用
7. 构建依赖树：

   route
   ├── db ← get_db
   └── user ← get_current_user
             ├── credentials ← security
             └── db ← get_db（复用同一个实例！）
```

**运行时**：收到请求 → 按依赖树从底往上执行 → 收集结果 → 调用路由函数。

### 1.2 依赖缓存（重要）

> **默认规则**：同一个请求中，同一个依赖项（同一个函数对象）**只执行一次**，结果被缓存复用。

所以：

```python
def route(
    db1 = Depends(get_db),
    user = Depends(get_current_user),   # 内部也有 Depends(get_db)
):
    # db1 和 get_current_user 内部的 db 是同一个对象！
```

**为什么这很重要？**

因为如果 `get_current_user` 用了另一个 Session，那么它查到的用户对象属于另一个事务——当你把这个 user 对象传给 service 并用 db1 操作时，可能出现跨会话问题。

**怎么关闭缓存？**

```python
Depends(get_db, use_cache=False)
```

**什么时候需要关闭？** 极少数情况，比如你需要两个独立的数据库会话（读写分离）。通常**不要关**。

### 1.3 `yield` 依赖的生命周期

```python
def get_db():
    db = SessionLocal()
    try:
        yield db          # ← 路由函数在这里执行
    except Exception:
        db.rollback()     # ← 路由抛异常时执行
    finally:
        db.close()        # ← 一定执行
```

**执行顺序**：

```
请求进来
  ↓
get_db() 开始 → 创建 Session
  ↓
yield db → 路由函数执行
  ↓
路由返回 / 抛异常
  ↓
回到 get_db 的 yield 之后 → except/finally 执行
  ↓
响应发给客户端
```

**关键认知**：`yield` 之后的代码**在响应生成之后才执行**（对于 `StreamingResponse`，是在流结束后）。

> ⚠️ **坑**：如果你的路由返回 `StreamingResponse`（如 SSE），`get_db` 的清理会等到流结束。如果客户端断开，可能触发异常。第 31 章会讲这个项目是怎么处理的。

## 二、三种依赖形态（回顾 + 深入）

### 形态 1：函数依赖

```python
def get_db() -> Generator[Session, None, None]:
    db = SessionLocal()
    try:
        yield db
    except Exception:
        db.rollback()
    finally:
        db.close()
```

**注意返回类型注解** `Generator[Session, None, None]`：

- 第一个 `Session`：yield 出去的类型
- 第二个 `None`：send 进来的类型（不用）
- 第三个 `None`：return 的类型（不用）

### 形态 2：类依赖（带参数）

```python
class RoleChecker:
    def __init__(self, required_role: str):
        self.required_role = required_role

    def __call__(self, user: User = Depends(get_current_user)) -> User:
        if user.role != self.required_role:
            raise BusinessException(code=403, message="权限不足")
        return user

admin_only = RoleChecker("admin")
teacher_only = RoleChecker("teacher")
```

**FastAPI 怎么知道它是依赖？**

因为 `admin_only` 是**实例**，`RoleChecker` 定义了 `__call__`，所以它是**可调用对象**。FastAPI 调用它，并解析 `__call__` 的参数作为子依赖。

**等价写法**（不用类）：

```python
def require_role(required_role: str):
    def checker(user: User = Depends(get_current_user)) -> User:
        if user.role != required_role:
            raise BusinessException(code=403, message="权限不足")
        return user
    return checker

admin_only = require_role("admin")
```

**用类还是闭包？**

| | 类 | 闭包 |
|---|---|---|
| 可读性 | 好（有名字、有属性） | 一般 |
| 可继承 | ✅ | ❌ |
| 调试 | 好（类型可见） | 一般 |

**推荐用类**——它更清晰，也能被 IDE 识别类型。

### 形态 3：嵌套依赖

```python
def get_current_user(
    credentials: HTTPAuthorizationCredentials = Security(security),
    db: Session = Depends(get_db),
) -> User:
    payload = decode_token(credentials.credentials)
    user = db.get(User, payload["user_id"])   # 查库确认状态
    if not user or user.status != 1:
        raise BusinessException(code=401, message="账号不可用")
    return user
```

**依赖深度没有限制**，FastAPI 会递归解析。

## 三、依赖注入最重要的能力：测试替换

**这是很多人不知道的技巧，也是依赖注入最大的价值。**

### 3.1 `dependency_overrides`

FastAPI 提供了覆盖依赖的机制：

```python
# tests/conftest.py
from fastapi.testclient import TestClient
from app.main import app
from app.database import get_db
from app.dependencies.auth import get_current_user

# 用测试数据库覆盖 get_db
def override_get_db():
    db = TestingSessionLocal()
    try:
        yield db
    finally:
        db.close()

# 用假用户覆盖 get_current_user
def override_get_current_user():
    return User(id=1, username="test", role="admin")

app.dependency_overrides[get_db] = override_get_db
app.dependency_overrides[get_current_user] = override_get_current_user

client = TestClient(app)
```

**这样测试时**：

- 不需要真实的数据库（用内存 SQLite）
- 不需要真实的 JWT（直接注入假用户）
- 每个测试可以注入不同角色（测试越权）

**测试越权变得非常简单**：

```python
def test_admin_only_endpoint():
    # 注入 student 用户
    app.dependency_overrides[get_current_user] = lambda: User(id=2, role="student")
    resp = client.post("/api/kb/documents", json={...})
    assert resp.status_code == 403     # 应该被拒绝

def test_admin_can_access():
    app.dependency_overrides[get_current_user] = lambda: User(id=1, role="admin")
    resp = client.post("/api/kb/documents", ...)
    assert resp.status_code == 200
```

> 💡 **面试话术**：「我用 FastAPI 的 `dependency_overrides` 做测试隔离。测试时用内存 SQLite 覆盖 `get_db`，用假用户对象覆盖 `get_current_user`。最大的好处是可以非常容易地测越权场景——注入一个 student 用户去调管理员接口，断言返回 403；再注入 admin 用户，断言 200。如果用全局变量，这些测试会很难写。」

### 3.2 项目里的测试结构

```python
# backend/tests/test_auth.py（简化）
import pytest
from fastapi.testclient import TestClient
from app.main import app
from app.dependencies.auth import get_current_user
from app.database import get_db

@pytest.fixture
def client(db_session, fake_user):
    app.dependency_overrides[get_db] = lambda: db_session
    app.dependency_overrides[get_current_user] = lambda: fake_user
    with TestClient(app) as c:
        yield c
    app.dependency_overrides.clear()    # ← 记得清理！否则影响其他测试

def test_admin_endpoint_requires_admin(client):
    ...
```

> ⚠️ **坑**：`dependency_overrides` 是**全局**的，测试之间会互相污染。必须在 fixture 结束或每个测试后 `clear()`。

## 四、作用域：四种依赖层级

FastAPI 支持在四个地方声明依赖：

```python
# 1. 路由级别（最常用）
@router.get("/labs", dependencies=[Depends(rate_limit)])
def list_labs(): ...

# 2. 函数参数级别（需要拿到返回值时）
def list_labs(user: User = Depends(get_current_user)): ...

# 3. Router 级别（整个 router 都生效）
router = APIRouter(dependencies=[Depends(get_current_user)])

# 4. App 级别（全局）
app = FastAPI(dependencies=[Depends(verify_api_key)])
```

| 层级 | 使用场景 | 能拿到返回值？ |
|---|---|---|
| 参数 | 需要用到依赖的结果（db、user） | ✅ |
| `dependencies=[...]` | 只需要副作用（鉴权、限流、日志） | ❌ |
| Router | 一组接口都需要（如 `/admin/*` 都要管理员） | ❌ |
| App | 全局（如 API Key 校验） | ❌ |

**Router 级别的典型用法**：

```python
# 知识库相关接口全部要求管理员
kb_router = APIRouter(
    prefix="/kb",
    dependencies=[Depends(admin_only)],   # ← 整个 router 生效
)

@kb_router.post("/documents")
def upload(...): ...      # 自动要求管理员

@kb_router.delete("/documents/{id}")
def delete(...): ...      # 自动要求管理员
```

> ⚠️ **这是项目里修复 B1 缺陷的做法** —— 知识库的 4 个接口原本用的是 `get_current_user`（只验登录不验角色），任何人登录都能上传/删除知识库文档。修成了 `get_current_admin`。
>
> 更彻底的做法是用 Router 级别依赖，这样新增接口也不会漏。

## 五、依赖注入 vs 全局变量：什么时候用哪个

| | 依赖注入 | 全局变量 |
|---|---|---|
| 配置（`settings`） | 可以用 | ✅ **推荐** |
| 数据库连接 | ✅ **必须** | ❌ |
| 当前用户 | ✅ **必须** | ❌（并发会串） |
| 模型（LLM、embedding） | 视情况 | ✅ 可以（单例） |
| 常量 | - | ✅ |

**判断标准**：

> **如果这个值「每个请求不同」，必须用依赖注入。**
> **如果「全局唯一且不变」，用全局变量（单例）没问题。**

**为什么当前用户必须用依赖注入？**

因为全局变量在并发下会串号——请求 A 设置 `current_user = 用户A`，请求 B 同时设置成用户B，A 的处理读到的是 B。**这是严重的安全事故。**

> ⚠️ **真实的错误做法**（很多新手会写）：
> ```python
> # ❌ 绝对不要这样
> _current_user = None
>
> def get_current_user():
>     global _current_user
>     _current_user = decode_jwt(...)
>     return _current_user
> ```
> FastAPI 的 `Depends` 保证每个请求有独立的依赖实例，不要自己用全局状态。

## 六、最小可运行骨架

```python
"""
di_demo.py —— 依赖注入的核心机制
运行：pip install fastapi uvicorn && python di_demo.py
演示：依赖树、缓存、yield 生命周期、测试覆盖、Router 级依赖
"""
from contextlib import asynccontextmanager

from fastapi import APIRouter, Depends, FastAPI, HTTPException, Security
from fastapi.security import HTTPAuthorizationCredentials, HTTPBearer
from fastapi.testclient import TestClient

# ══════════════════════════════════════════════════════════
# 依赖定义
# ══════════════════════════════════════════════════════════

CALL_LOG = []      # 记录依赖调用顺序
DB_COUNTER = 0     # 统计 get_db 被调用了几次

class FakeSession:
    def __init__(self, sid: int):
        self.sid = sid
    def __repr__(self):
        return f"<Session#{self.sid}>"

def get_db():
    """yield 依赖：负责生命周期。"""
    global DB_COUNTER
    DB_COUNTER += 1
    db = FakeSession(DB_COUNTER)
    CALL_LOG.append(f"  → get_db 创建 {db}")
    try:
        yield db
        CALL_LOG.append(f"  → get_db 正常结束 {db}")
    except Exception as e:
        CALL_LOG.append(f"  → get_db 异常回滚 {db}: {type(e).__name__}")
        raise
    finally:
        CALL_LOG.append(f"  → get_db 关闭 {db}")

security = HTTPBearer(auto_error=False)

class User:
    def __init__(self, uid: int, role: str):
        self.id, self.role = uid, role
    def __repr__(self):
        return f"<User#{self.id} {self.role}>"

TOKENS = {"t-admin": User(1, "admin"), "t-student": User(2, "student")}

def get_current_user(
    credentials: HTTPAuthorizationCredentials = Security(security),
    db = Depends(get_db),        # ← 嵌套依赖，会复用同一个 db
) -> User:
    CALL_LOG.append(f"  → get_current_user 拿到的 db 是 {db}")
    if credentials is None:
        raise HTTPException(status_code=401, detail="缺少认证")
    user = TOKENS.get(credentials.credentials)
    if not user:
        raise HTTPException(status_code=401, detail="token 无效")
    CALL_LOG.append(f"  → get_current_user 返回 {user}")
    return user

class RoleChecker:
    """类依赖：带参数的权限检查。"""
    def __init__(self, role: str):
        self.role = role

    def __call__(self, user: User = Depends(get_current_user)) -> User:
        CALL_LOG.append(f"  → RoleChecker({self.role}) 检查 {user}")
        if user.role != self.role:
            raise HTTPException(status_code=403, detail=f"需要 {self.role} 权限")
        return user

admin_only = RoleChecker("admin")

def rate_limit():
    """副作用依赖：不需要返回值，只做检查。"""
    CALL_LOG.append("  → rate_limit 执行")
    # 真实实现：检查 Redis 计数
    return True

# ══════════════════════════════════════════════════════════
# 应用
# ══════════════════════════════════════════════════════════

app = FastAPI(title="依赖注入演示")

@app.get("/public")
def public():
    return {"message": "无需鉴权"}

@app.get("/me")
def me(
    db = Depends(get_db),
    user: User = Depends(get_current_user),
):
    """演示依赖缓存：db 和 get_current_user 内部的 db 是同一个。"""
    return {"user_id": user.id, "role": user.role, "db": repr(db)}

@app.post("/admin/documents", dependencies=[Depends(rate_limit)])
def upload(user: User = Depends(admin_only)):
    """演示：类依赖 + dependencies 副作用依赖。"""
    return {"message": f"管理员 {user.id} 上传成功"}

@app.get("/boom")
def boom(db = Depends(get_db)):
    """演示 yield 依赖的异常分支。"""
    raise RuntimeError("故意炸掉，看 get_db 的 except 分支")

# Router 级依赖：整组接口都要鉴权
secure_router = APIRouter(prefix="/secure", dependencies=[Depends(get_current_user)])

@secure_router.get("/data")
def data():
    """不需要在函数里声明 get_current_user，Router 级已经保证。"""
    return {"data": "敏感数据"}

app.include_router(secure_router)

# ══════════════════════════════════════════════════════════
# 演示
# ══════════════════════════════════════════════════════════

def demo_call_order():
    print("【1. 依赖调用顺序】调用 /me")
    CALL_LOG.clear()
    client = TestClient(app)
    r = client.get("/me", headers={"Authorization": "Bearer t-admin"})
    print(f"  响应: {r.json()}")
    print("  依赖执行顺序：")
    for line in CALL_LOG:
        print(line)
    print()

def demo_cache():
    print("【2. 依赖缓存：get_db 被调用了几次？】")
    CALL_LOG.clear()
    global DB_COUNTER
    before = DB_COUNTER
    client = TestClient(app)
    client.get("/me", headers={"Authorization": "Bearer t-admin"})
    print(f"  get_db 调用次数: {DB_COUNTER - before}")
    print(f"  {'✅ 只调用 1 次（缓存生效）' if DB_COUNTER - before == 1 else '❌ 调用了多次（缓存失效）'}")
    print("  含义：路由里的 db 和 get_current_user 里的 db 是同一个 Session")
    print("  这保证了事务一致性\n")

def demo_override():
    print("【3. 测试覆盖：dependency_overrides】")
    client = TestClient(app)

    # 先测：student 访问管理员接口 → 403
    r1 = client.post("/admin/documents", headers={"Authorization": "Bearer t-student"})
    print(f"  student 访问管理员接口: {r1.status_code} {r1.json().get('detail')}")

    # admin 访问 → 200
    r2 = client.post("/admin/documents", headers={"Authorization": "Bearer t-admin"})
    print(f"  admin 访问管理员接口:   {r2.status_code} {r2.json()}")

    # 用 override 注入假用户（不需要真实 token）
    app.dependency_overrides[get_current_user] = lambda: User(999, "admin")
    r3 = client.post("/admin/documents")
    print(f"  override 假用户后:      {r3.status_code} {r3.json()}")

    # ⚠️ 清理，否则影响后续测试
    app.dependency_overrides.clear()
    r4 = client.post("/admin/documents")
    print(f"  clear 之后:             {r4.status_code} (应回到 401/403)")
    print()

def demo_exception_branch():
    print("【4. yield 依赖的异常分支】")
    CALL_LOG.clear()
    client = TestClient(app, raise_server_exceptions=False)
    try:
        client.get("/boom")
    except Exception:
        pass
    print("  依赖执行顺序：")
    for line in CALL_LOG:
        print(line)
    print("  ✅ 可以看到异常时走了 except 分支（真实项目里这里做 rollback）\n")

def demo_router_level():
    print("【5. Router 级依赖】")
    client = TestClient(app)
    r1 = client.get("/secure/data")
    print(f"  无 token 访问 /secure/data: {r1.status_code} {r1.json().get('detail')}")
    r2 = client.get("/secure/data", headers={"Authorization": "Bearer t-student"})
    print(f"  有 token 访问:              {r2.status_code} {r2.json()}")
    print("  ✅ 函数里没写 get_current_user，但 Router 级已保证鉴权")
    print("  ✅ 好处：新增接口不会漏掉鉴权\n")

if __name__ == "__main__":
    print("=" * 62)
    print("FastAPI 依赖注入机制演示")
    print("=" * 62 + "\n")
    demo_call_order()
    demo_cache()
    demo_override()
    demo_exception_branch()
    demo_router_level()
```

**跑一遍你会看到**：

1. 依赖的**执行顺序**（从底往上）
2. `get_db` **只调用一次**（缓存生效）
3. 测试覆盖的**威力**（注入假用户、测越权）
4. 异常时的 **except 分支**

### 7.1 `dependencies/auth.py`

```python
security = HTTPBearer()

def get_current_user(
    credentials: HTTPAuthorizationCredentials = Security(security),
    db: Session = Depends(get_db),
) -> User:
    token = credentials.credentials
    payload = decode_token(token)
    if not payload:
        raise BusinessException(code=401, message="登录已失效")
    user = db.get(User, payload["user_id"])      # ★ 查库确认状态
    if not user or user.status != 1:
        raise BusinessException(code=401, message="账号不可用")
    return user

def get_current_admin(current_user: User = Depends(get_current_user)) -> User:
    if current_user.role != "admin":
        raise BusinessException(code=403, message="需要管理员权限")
    return current_user
```

**两个依赖的关系**：`get_current_admin` 依赖 `get_current_user`，再加一层角色判断。

> ⚠️ **这是 B1 缺陷的修复**。原本知识库的 4 个接口用的是 `get_current_user`（只验登录），任何人登录都能上传/删除知识库文档。改成 `get_current_admin` 后才真正限制住。

        yield db
    except Exception:

## 本章速记卡

1. **依赖注入解决的问题**：组件怎么拿到它需要的、每个请求不同的东西。
2. **依赖树在启动时构建**，运行时从底往上执行。
3. **依赖缓存：同一请求内同一依赖只执行一次**。所以 db 是共用的（保证事务一致）。
4. **`yield` 依赖**：yield 前 = 请求前，yield 后 = 响应后。
5. **三种形态**：函数、类（`__call__`）、嵌套。
6. **四种作用域**：参数、`dependencies=[]`、Router、App。
7. **`dependency_overrides` 是测试利器**：注入假 DB、假用户，轻松测越权。
8. **记得 `clear()`**，否则测试互相污染。
9. **Router 级依赖防漏**：新增接口自动继承鉴权。
10. **每个请求不同的值必须用依赖注入**，全局变量会串号（严重安全事故）。

## 面试问答：依赖注入

### Q1：「FastAPI 的依赖注入是怎么工作的？」

**满分答法**：

> 启动时，FastAPI 扫描路由函数的参数，发现默认值是 `Depends(xxx)` 就把它当依赖。然后递归分析这个依赖自己的签名——如果它也有 `Depends`，继续往下解析，构建出一棵依赖树。
>
> 运行时，收到请求后按这棵树从底往上执行，把结果收集起来，最后调用路由函数。
>
> 有两个关键机制：
>
> **一是缓存**。同一个请求内，同一个依赖函数只执行一次，结果复用。比如路由里 `Depends(get_db)` 和 `get_current_user` 内部的 `Depends(get_db)` 拿到的是同一个 Session，这保证了事务一致性。可以用 `use_cache=False` 关掉，但通常不应该。
>
> **二是 yield 生命周期**。如果依赖函数用 `yield` 而不是 `return`，那么 yield 之前的代码在请求处理前执行，yield 之后的代码在响应生成后执行。我用它做数据库会话的 rollback 和 close，保证一定会被清理。

---

### Q2：「依赖注入带来什么好处？」

**满分答法**：

> 四个，最重要的是可测试性。
>
> **一是可测试**。FastAPI 提供 `dependency_overrides`，测试时能替换掉任何依赖。我用内存 SQLite 覆盖 `get_db`，用假用户对象覆盖 `get_current_user`。最大的价值是可以非常容易地测越权场景——注入一个 student 用户去调管理员接口，断言 403；再注入 admin，断言 200。如果用全局变量，这些测试会很难写。
>
> **二是显式依赖**。看函数签名就知道它需要什么（db、user、limiter），不用去函数体里找。
>
> **三是生命周期管理**。yield 保证清理一定执行，不会泄漏数据库连接。
>
> **四是可复用**。鉴权、限流这些逻辑写一次，所有接口声明就能用。

---

### Q3：「什么时候用依赖注入，什么时候用全局变量？」

**满分答法**：

> 判断标准很明确：**如果这个值每个请求可能不同，必须用依赖注入；如果全局唯一且不变，用全局变量（单例）没问题**。
>
> 数据库会话、当前用户、请求级别的限流器——这些每个请求不同，必须依赖注入。
>
> 配置（settings）、模型实例（LLM 客户端、embedding 模型）——这些全局唯一、初始化后不变，用模块级单例就行。我的 `settings = Settings()` 和 embedding 模型都是单例。
>
> 特别要强调：**当前用户绝对不能用全局变量存**。我见过有人写 `global _current_user` 然后在依赖里赋值——这在并发下会串号，请求 A 可能读到请求 B 的用户身份，这是严重的安全事故。依赖注入的价值就在于 FastAPI 保证每个请求有独立的依赖实例。

---

### Q4：「Router 级依赖有什么用？」

**满分答法**：

> 最大的价值是**防止漏判权限**。
>
> 如果鉴权写在每个路由函数的参数里，那么新增接口时可能忘记加。而 Router 级依赖是「整组生效」——比如 `APIRouter(prefix="/kb", dependencies=[Depends(get_current_admin)])`，那么这个 router 下所有接口自动要求管理员，新增接口不需要记得加。
>
> 我这项目就踩过这个坑：知识库的 4 个接口原本每个都用 `get_current_user`，只验登录不验角色，结果任何登录用户都能上传和删除知识库文档。后来改成 `get_current_admin`。更彻底的做法是提到 Router 级别，从机制上杜绝遗漏。
>
> 另外还有 `dependencies=[...]` 这种形式——当你不需要依赖的返回值、只需要它的副作用时（比如限流、审计日志），用这个比写成参数更清晰。

---

### Q5：「测试怎么隔离？」

**满分答法**：

> 三层隔离：
>
> **数据库隔离**：用内存 SQLite（`:memory:`）或者每个测试一个临时文件，通过覆盖 `get_db` 实现。每个测试用例跑完清空表。
>
> **身份隔离**：覆盖 `get_current_user`，注入不同角色的假用户，用来测越权。
>
> **外部依赖隔离**：大模型调用注入 FakeLLM（返回预设的 tool_calls），这样执行路径确定、可断言、而且毫秒级完成。真模型又慢又不稳定，不适合单元测试。
>
> 有个坑要注意：`dependency_overrides` 是**全局字典**，测试之间会互相污染。我会在 fixture 的 teardown 里 `clear()`，保证每个测试独立。
>
> 另外我项目里 Agent 的测试还有个特殊做法：注入假 LLM 后，可以精确断言「审批节点有没有触发」「工具重试了几次」「历史被裁剪成几条」——因为整个执行路径是确定的。

---

### Q6：「如果依赖解析失败会怎样？」

**满分答法**（这题考异常处理）：

> 看失败发生在哪一层：
>
> 如果是依赖函数自己抛了 `BusinessException` 或 `HTTPException`（比如 token 无效、权限不足），它会被异常处理器捕获，转成对应的 HTTP 响应，路由函数**根本不会执行**。这正是我们想要的——鉴权失败不应该进入业务逻辑。
>
> 如果是依赖函数抛了未捕获的异常（比如数据库连不上），会走兜底异常处理器，返回 500。
>
> 有个细节：如果依赖是 `yield` 形式，那么异常发生时，**yield 之后的 except/finally 仍然会执行**（这是 Python 生成器语义保证的）。所以我在 `get_db` 里写的 rollback 和 close 一定会跑。但如果异常发生在依赖解析阶段（还没到 yield），那就不会执行——因为它还没开始。
>
> 另外如果依赖抛异常，FastAPI 不会继续执行后续依赖，直接短路了。

## 常见坑

### 坑 1：`dependency_overrides` 忘了 clear

测试互相污染，某些测试莫名其妙失败。

### 坑 2：用全局变量存当前用户

并发串号，严重安全事故。

### 坑 3：`use_cache=False` 导致多个 Session

事务断裂，可能出现脏读。

### 坑 4：以为 `dependencies=[...]` 能拿到返回值

不能。需要返回值就用参数形式。

### 坑 5：Router 级依赖和函数级依赖重复声明

会导致依赖执行两次（不过有缓存，一般无害，但代码冗余）。

### 坑 6：`yield` 依赖里忘了 try/finally

异常时资源泄漏。

### 坑 7：循环依赖

A 依赖 B，B 又依赖 A。FastAPI 会报错。解法是提取公共依赖到第三层。
