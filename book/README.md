# 《从零到起飞：AI Agent 工程实战》

> 副标题：以「智能实验室预约系统」为主线的全栈 Agent 开发教程
> 面向读者：想入行 AI Agent 开发的工程师、准备面试的求职者
> 全书规模：6 卷 · 47 章 · **已完成约 95 万字**（原定目标 35 万字）

---

## 这本书是什么

这不是一本讲概念的书，是一本**跟着真实代码长出来的书**。

市面上大多数 Agent 教程的问题是：给你一个玩具 Demo，跑通了，然后你面试时什么也讲不出来——因为玩具没有真实工程的复杂度：没有并发冲突、没有鉴权、没有上下文膨胀、没有工具超时、没有评测。

这本书的主线是一个**真实跑起来的全栈项目**：智能实验室预约系统。它有：

- 31 个 REST 接口、37 个单元/集成测试
- 一个 LangGraph 状态机 Agent（带持久化、人工审批、上下文裁剪）
- 一条完整 RAG 管线（切块 → 双路召回 → 融合 → 重排 → 父上下文 → 引用溯源）
- 一套离线评测体系（RAGAS 四指标 + 检索指标 + 裁判分离）
- 一个 Vue3 前端（SSE 流式、Markdown 渲染、角色守卫）

全书每一章都遵循同一个结构，这个结构是为了**让你能讲出来**而设计的：

```
为什么需要它 → 它到底是什么 → 最小骨架（能跑）→ 项目里怎么用的 → 踩过的坑 → 面试怎么答
```

## 三种读法

**路径 A：面试突击（7 天）**
只读每章的「面试问答」+「速记卡」，外加第 02、15、18、19、26、37、44 章全文。
目标：能讲清楚项目，但深度有限。

**路径 B：系统学习（30 天）**
按顺序读，每章跑通最小骨架。
目标：真正掌握，能回答追问。

**路径 C：工程参考（随时）**
遇到问题查对应章节的「项目代码定位」。
目标：解决手头问题。

## 代码约定

全书引用的项目代码遵循以下约定：

- 路径以项目根目录为基准，如 `backend/app/services/agent_service.py`
- 行号引用格式 `文件:行号`，如 `agent_service.py:268`
- 所有代码片段均来自真实项目，未经美化
- 标有「⚠️」的是真实踩过的坑

项目关键文件速查：

```
backend/app/
├── main.py                    # FastAPI 入口、lifespan、异常处理

├── database.py                # 引擎、SessionLocal、get_db

├── api/                       # 9 组路由（31 个接口）
```

## 关于这本书的诚实说明

书里会明确标注哪些技术是**实机验证过**的，哪些只是**了解**。真实情况是：

- ✅ 实跑：Chroma、pgvector、LangGraph、RAGAS、FastMCP、SSE
- ⚠️ 未实跑：Milvus（代码接口已实现，未起服务）
- ⚠️ 未配置：Redis（代码已接入，`.env` 里为空，优雅降级）

面试时按这个口径回答，任何追问都不会露馅。

## 写完之后又发现的缺陷（诚实补记）

写这本书的过程中，因为要逐章核对代码，又发现了几个原来的审查没覆盖的问题。它们已写进对应章节，这里汇总一下：

| 缺陷 | 位置 | 章节 |
|---|---|---|
| 兜底异常处理器不记日志，线上 500 无迹可寻 | `common/exceptions.py:50-55` | 40 |
| 健康检查 `GET /` 不查任何依赖 | `main.py:84-87` | 40 |
| `docker-compose.yml` 起了 PostgreSQL 但没跑 `alembic upgrade head` | `docker-compose.yml` | 42 |
| 无 `.dockerignore`，`.env` 会进镜像 | `backend/Dockerfile` | 42 |
| MCP Server 未在 compose 定义但 `MCP_ENABLED=true` | `docker-compose.yml` | 42 |
| nginx 缺 `proxy_read_timeout`，60 秒会切断 SSE | `frontend/nginx.conf` | 42 |
| token 估算 `(len+3)//4` 对中文低估 3-4 倍 | `agent_service.py:176-190` | 41 |
| `/uploads` 静态目录无鉴权 | `main.py:81` | 46（D3） |

**这些都没修**（本书只做文档，不改代码）。它们是最好的面试素材——**能主动说出自己项目的缺陷和修复方案，比声称"都做好了"可信得多。**

## 全书结语

这本书想给的不是一份可以背的知识点清单，而是一套"遇到问题时怎么想"的框架。全书反复出现的是同一个动作：

```
看到一个现象 → 问"它为什么这样" → 找到根因 → 给出可验证的方案 → 说清边界
```

读完不等于会了。**唯一能证明你会了的，是你自己敲一遍、跑一遍，然后被一个 bug 卡住两天。** 第 43 章那 21 天路线图存在的意义就是这个。

Agent 领域变化极快——你现在学的 LangGraph API 半年后可能就变了（第 39 章坑 6 讲过 RAGAS 0.3→0.4 的大改）。**但这本书想教的是那些不会变的部分**：状态机、上下文预算、工具的错误处理、检索的评估口径、降级的副作用。
